# FoodieHub — Mobile App (Flutter)

A real Android + iOS app for your FoodieHub site. It talks to the JSON API
in the `api/` folder that was added to your PHP website — same database,
same business logic, same orders your admin panel already manages.

## What's included

`lib/` — the entire app: models, API client, state management (auth &
cart), and every screen (splash, login/register, home with categories +
search, food detail with ratings, cart, checkout, order success/history/
detail, account). `pubspec.yaml` lists the packages it depends on.

**Not included yet:** `android/`, `ios/`, and other platform folders. This
sandbox can't run the Flutter SDK, so those get generated by the SDK itself
in step 2 below — a completely normal, standard step for any Flutter
project and nothing to worry about.

## One-time setup

1. **Install Flutter** (if you haven't already): https://docs.flutter.dev/get-started/install
   Then run `flutter doctor` and follow any prompts (Android Studio for
   Android builds, Xcode for iOS builds — iOS builds only work on a Mac).

2. **Generate the platform folders.** Open a terminal in this project folder
   (the one with `pubspec.yaml` in it) and run:
   ```
   flutter create .
   ```
   This adds `android/`, `ios/`, etc. around your existing `lib/` and
   `pubspec.yaml` without touching them — it's the standard way to turn a
   lib-only Flutter project into a buildable one.

3. **Point the app at your live website.** Open `lib/config.dart` and change:
   ```dart
   static const String baseUrl = 'https://YOUR-DOMAIN.com/foodapp';
   ```
   to your actual domain (must be HTTPS, and must be where you deployed the
   `foodapp` folder — API included).

4. **Install packages:**
   ```
   flutter pub get
   ```

5. **Run it** (with a device/emulator connected or open):
   ```
   flutter run
   ```

## Building for release

**Android (.apk or .aab for Play Store):**
```
flutter build apk --release
# or, for Play Store upload:
flutter build appbundle --release
```
Output lands in `build/app/outputs/`. You'll need a Google Play Developer
account ($25 one-time) to publish.

**iOS (.ipa, Mac + Xcode required):**
```
flutter build ipa --release
```
You'll need an Apple Developer account ($99/year) and to set up signing in
Xcode (`open ios/Runner.xcworkspace`) before this works.

## Before you publish

- **App icon & name:** replace the default Flutter icon/name. The
  [flutter_launcher_icons](https://pub.dev/packages/flutter_launcher_icons)
  package automates this — add your logo and run one command.
- **App name:** edit `android/app/src/main/AndroidManifest.xml`
  (`android:label`) and `ios/Runner/Info.plist` (`CFBundleDisplayName`).
- **Test end-to-end** against your live server before submitting to either
  store: register, browse, add to cart, checkout, and check the order shows
  up correctly in your admin panel.

## Current scope

- Cash on Delivery only (matches what the API supports right now — see
  `api/README.md` on the server for how to extend it to Razorpay/UPI-QR
  later).
- Customer-facing only. Admin, restaurant-partner, and delivery-partner
  panels remain website-only, same as before.
